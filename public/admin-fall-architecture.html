Internal · Fall 2026 Admin · Architecture & Accountability

Why this admin won't break like the last one.

The summer admin collapsed under 70 founders: request storms, stale mirrors, contradictory statuses, and a Google Sheet that sprawled to 70+ tabs. This doc puts the fall build explicitly against those failures: what was corrected, which bugs are structurally impossible now, and the honest list of what remains.

Failure by failure: summer vs fall
What broke in summerRoot causeHow fall fixes it structurally
The dashboard buckled at 70 founders: slow loads, timeouts, tabs that never finished. The browser fanned out API calls per founder per tab. 70 founders meant 70+ requests on every view, each hitting Sheets separately. One request powers the whole admin. /api/admin/fall-overview aggregates milestones, meetings, pulse, and wins in 3 bulk reads server-side (one Sheets batch, one Typeform page, one milestones read), cached 60s. Load is identical at 3 founders or 300.
"Crosshairs": tabs contradicted each other and nobody trusted the numbers. Statuses were hand-set and mirrored into the sheet, then drifted from reality. Data had no visible age. Nothing is hand-set. Every status is computed from the sources of truth on every request via the fall rulebook. The header shows exactly how old the data is ("Data as of 1:33 PM, 0s ago") with a force-refresh button and 60s auto-refresh. Two tabs can't disagree because there is one payload.
The Google Sheet sprawled to 70+ tabs, one per person, and became unnavigable and fragile. save-response created a tab per founder; every bulk read became a fan-out; renames and deletions broke silently. Four tabs, total, mirroring the admin: FallResponses (every portal input, one row each), FallMentees (application decisions), FallMentors (mentor decisions), FallMatches (pairings). Fall founders' portal saves route to FallResponses automatically; per-person tabs are never created again.
Matching was clunky and broke whenever new candidates or applications arrived. Matching worked off frozen imports and spreadsheets copied at a point in time; new applicants didn't exist until someone re-imported. Applicants stream live from the original Typeforms on every load: new applications simply appear, already parsed, scored, and filterable. Matches append to FallMatches instantly. When a stronger mentor enters the pool for someone already matched, a better-fit flag raises itself.
Late matches broke every deadline and needed hand-patched slug lists (HOLDING_SLUGS, LATE_MATCH_SLUGS, VERY_LATE_MATCH_SLUGS). Deadlines were welded to summer calendar weeks, so any human delay demanded a code patch. No patch lists exist in the fall build. The rulebook uses program-level dates today and moves to per-match rolling clocks with the ingest, so a late match automatically gets a fair schedule instead of a code change.
Fifteen-plus tabs with unclear ownership; finding "what do I do now" took archaeology. Tabs accreted per crisis with no funnel model. The tabs are the funnel: Mentee Apps → Mentor Apps → Accepted Founders / Accepted Mentors → Matching → Matched, plus Roster, Sessions, Pulse & Wins, and a 📋 Today queue that sorts every open action by urgency (risk → warning → info, oldest first), check-off-able, with Today / Yesterday / N-days-overdue aging.
Verification piled up at the end: attendance reconstructed from CSVs, signatures chased in the final week. No as-you-go pipeline; everything reconciled at the finish. As-you-go by design: meetings submit at the moment they happen and count live; Luma registrations sync every 5 minutes; every portal input also posts to #uplift-portal-inputs; BreezeDoc signatures close the loop at the end instead of opening it.
Bugs this architecture makes structurally hard
  • Request storms: the browser makes at most three data requests (overview, people, sessions), each bulk, each cached. Founder count no longer multiplies anything.
  • Stale mirrors: there are no mirrors. Derived values (status, gate, eligibility, match grades) are computed at read time and never written back.
  • Silent truncation: Typeform reads pull 1000 responses per form (current volume: ~116/63); Luma listing paginates all pages (the summer bug that silently dropped July events is fixed and carried over).
  • Orphan people: applicants can't fall out of the system between import cycles because there are no import cycles; the forms are read live.
  • Conflicting decisions: approvals, rejections, and matches are append-only rows with last-write-wins reads, so history is never destroyed and any decision can be undone with an "undo" or "unmatch" without touching the sheet by hand.
  • Sheets quota blowups: batch reads plus 60s / 5min caches keep API usage flat; a stampede of admin refreshes costs one upstream read.
  • Portal saves failing on side effects: Slack posting is fire-and-forget and the whole save path degrades gracefully; a Slack or Sheets hiccup can't lose a founder's Deep Work.
The clean backend: four tabs, mapped to the admin

FallResponses

Every portal input, one row: slug, week, field, question, value, timestamp. Feeds Roster, Pulse & Wins, and the Week 1 gate.

FallMentees

Application decisions (approve / reject / undo), append-only. Feeds the Accepted Founders tab and the Matching queue.

FallMentors

Mentor decisions, same shape. Feeds Accepted Mentors and the match pool.

FallMatches

Pairings with timestamps and status. Feeds the Matched tab and better-fit flags.

Existing tabs that stay: Milestone Dashboard and Participation (milestones, written by the same APIs as summer so nothing live breaks), SessionReview and LumaAttendance (verification pipelines). The original Typeforms (hAbo7Jdh, AayoroO1, e0L62296) remain the source of truth for applications and meetings.

What the admin now tracks
  • Pre-program goals: 100 mentee + 100 mentor applications by Sept 3, 80 of each qualified, live progress bars with a day countdown.
  • Program & cohort health: statuses, Week 1 gate completion, meeting and edu averages, per cohort and whole-program.
  • Session logistics: 22/22 sessions live on Luma, registration counts synced every 5 minutes, and the current gap: sessions still needing speakers, titles, and descriptions.
  • Matching quality: every suggestion graded (Perfect / Excellent / Strong / Good / Weak) from session-tier alignment (the heaviest weight), focus overlap, shared language between what founders want and mentors offer, stage fit, and scheduling.
  • Pulse and wins: the green/yellow/red grid and the Tuesday-update wins feed with one-click copy.
  • Meeting clocks (⏱ Deadlines): per matched founder, rolling due dates for Discover / Act / Roadmap and the 180-minute meter, color-coded by days remaining.
  • Grant evidence (📊 Reporting): per-founder completion table, verified sessions vs submitted meetings and minutes, edu, OverdriveAI, exit survey, BreezeDoc signature, certificate, with one-click CSV export for the NJEDA package.
  • Ulrike, the portal chat bot: every founder question answered from the same computed state this admin reads, uncertain answers routed to uplift@, every exchange logged to #uplift-portal-inputs.
